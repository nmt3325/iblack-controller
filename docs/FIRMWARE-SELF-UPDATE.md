# iBlack / iermu 自作ファーム更新の実現性調査

## 結論

メーカーの新しい配布ファームや稼働中の更新サーバーがなくても、ダンプに含まれる `SysUpdate` のローカル更新経路を使って、自作した内容を端末のアプリ領域へ書き込める見込みは高い。単なる暗号化の往復だけでなく、実際のARM機械語でヘッダー受信・CRC検査・命令振分け・復号・消去・書込み・成功応答・fsync・再起動要求まで進むことを、RAM上の仮想フラッシュで確認した。

**実機への接続、送信、消去、書込み、再起動は行っていない。自作ファームの起動成功を実証したものではない。テストに使用した任意データ自体は起動用ファームではなく、実機へ送ってはいけない。**

## 対象の固定

- 8 MiB原本 `iblack_1.bin`：SHA-256 `b3e0ff253ed30696af53ecadb4ccf4e4220c6d6c6e38ce6730f4fe86e4a80da0`。
- 解析対象 `usr/bin/SysUpdate`：SHA-256 `c76e218d9dffde035ca5ed28cae89fa2dd679c539f647f6329f8dcf083e0c6d9`。
- 別ビルドを誤ったアドレスで解析しないよう、エミュレータはELFのSHA-256不一致時に停止する。
- 参照元のローカルGit HEAD：`7c09cfb854874aba3821983a58fa479a18d2546b`。対象ELFにローカル変更はなかった。

解析対象：[^https://github.com/nmt3325/iblack-controller/blob/7c09cfb854874aba3821983a58fa479a18d2546b/firmware/iblack-8m/extracted/base_rootfs/usr/bin/SysUpdate]

## 確認できたローカル更新処理

- `SysUpdate` には TCP 3508 の待受処理がある。現行実機で待受中かは未確認。
- 28バイトのヘッダーを受け、CRC32を検証して命令コードで分岐する。
- 今回の `0x94` / `0x96` 経路では、CRC32とダンプ内から再現できる対称暗号の検査を通過すれば書込みへ進む。メーカーの秘密署名鍵やクラウド承認を必要とする処理は、この検証した経路にはなかった。
- RC6の鍵スケジュール・nonce設定・暗号化・復号は、ダンプの関数をそのまま実行した。暗号方式を推測して独自実装しただけの検証ではない。
- nonceの時刻条件もある。保守用の値を使う既存分岐があることと、期限切れ拒否の両方を検証した。
- これは「すべての更新経路に署名がない」「SoCのSecure Bootがない」という主張ではない。

### 命令ごとの到達点

| 命令 | 対象 | 今回の検証 |
| --- | --- | --- |
| `0x94` | `/dev/mtd5`（bakfs） | 実際の書込み関数 `0x9498` を実行。任意データが所定の保存形式で書き込まれることを確認 |
| `0x96` | `/dev/mtd2`（appfs）と `/dev/mtd5`（bakfs） | 実際のヘッダー受信 `0xcb58` から開始。CRC・振分け・検査・消去・両領域への書込み・成功応答・fsync・closeまで実行し、再起動関数 `0x8c74` の入口で停止 |
| `0x91` | `/dev/mtd0`（boot） | 分岐と書込み処理の存在を静的確認。今回の書込み成功テストの対象外 |

**重要：`0x96` は稼働用appfsとbakfsの両方を更新する。バックアップ領域があるから元に戻せる、とは考えないこと。**

## オフライン実証結果

### 書込み関数：15ケース

`offline_write_proof.py` / `offline_write_report.json`

- 正常系9件：任意データの長さ 1 / 12 / 13 / 16 / 63 / 64 / 65 / 4093 バイト、および保守用時刻条件。
- 異常系6件：暗号文CRC不正、平文CRC不正、マジック不正、形式種別不正、期限切れ、最大長超過。
- 正常系は書込み内容・保存用ヘッダー・残り領域の消去状態・成功応答・応答CRC・入力消費を確認。
- 異常系は拒否され、仮想フラッシュが一切変更されないことを確認。

### 実際の入口からappfs更新：4ケース

`offline_appfs_proof.py` / `offline_appfs_report.json`

- 正常系：4093バイトの自作テスト内容がappfsへそのまま、bakfsへ8バイトの管理ヘッダー付きで書き込まれた。
- 入力、appfs、bakfs内ペイロードのSHA-256がすべて一致：`62fc20547b02e03b784c2e631292b2582e39e48e8458cdffe214eb3a26711c87`。
- ヘッダーCRC、暗号文CRC、平文CRCを壊す3ケースは、それぞれ書込み前に拒否された。
- 仮想パーティションはappfs / bakfs各2560 KiB、消去単位64 KiB。各40ブロック、計80回の消去要求、2回のwrite、2回のfsyncとcloseを記録した。
- 正常系は最終成功応答 `0xfe, 0` とACK受信を経て再起動要求へ進んだ。再起動関数自体は実行せず入口で停止した。

**合計19ケース（正常系10・異常系9）が成功。別途、パッケージ形式・CRC・暗号化往復の7ケースも成功。**

## 検証の分離と限界

- ARM命令、CRC、暗号、更新条件、消去・書込みループ、応答生成はダンプのコードを実行した。
- `recv` / `send` はメモリのキュー、MTDはPythonのbytearrayへ置換した。OS呼出しは許可リストで処理し、未知の呼出しや割込みは停止する。
- watchdogのMMIOアドレスは私有RAMへ向けた。実機の物理メモリへ触れていない。
- 実ネットワーク接続、ホストのシェル命令、実デバイスへの書込みはいずれも0。
- 実機の待受・ファーム版・MTD構成・物理消去単位、完全な起動可能イメージのサイズ上限、カーネルやドライバー互換性、起動成功は未検証。
- エミュレータでの受理は、物理フラッシュの保護状態や実機の起動成功を保証しない。

## ダンプに含まれるパーティション構成

U-Boot環境の `mtdparts` より。実機の現状とは別途照合が必要。

| デバイス | 名前 | オフセット | 大きさ |
| --- | --- | --- | --- |
| mtd0 | boot | 0x000000 | 2048 KiB |
| mtd1 | rootfs | 0x200000 | 768 KiB |
| mtd2 | appfs | 0x2c0000 | 2560 KiB |
| mtd3 | mdat1 | 0x540000 | 128 KiB |
| mtd4 | mdat2 | 0x560000 | 128 KiB |
| mtd5 | bakfs | 0x580000 | 2560 KiB |

U-Bootの `bootcmd` はSPIの `0x80000` から `0x180000` バイトを読み、`bootm` する設定。boot領域は単純なアプリ領域ではなく、起動処理やカーネルを巻き込む。最初から全8 MiBを更新パケットとして投げたり、boot / mdat領域を試し書きしたりしない。

## 推奨する次の段階

1. 実機のファーム版・全フラッシュバックアップ・固有設定を確認し、UARTでの起動ログ取得やSPIからの復旧手段を確保する。
2. 最初は既存のカーネル、ドライバー、センサー関連を残し、appfs内の起動スクリプトや自作アプリだけを最小変更する方針が妥当。完全自作OSへの置換は別の検証課題。
3. ファイルシステム形式、サイズ、アラインメント、実際のマウント・起動条件を確認して起動可能イメージを作る。生の8 MiBダンプと転送用パッケージを混同しない。
4. 作成したイメージをオフラインで復号照合・内容検査してから、実機書込みは別工程として明示的な承認のもとで行う。今回のコードには実機送信機能を含めない。

## 技術メモ・以前の仮説の訂正

- 転送ボディのヘッダーは32バイト。以前の試作の28バイトは誤りだった。
- ボディ先頭はBE32マジック `0x01000001`、次が元イメージ長、次が形式種別 `5`。末尾の暗号文CRCはオフセット0x1c。暗号文は0x20から。
- 暗号化前のデータは「イメージ＋0埋め＋末尾4バイトの平文CRC」で16バイト境界にする。平文CRCのない暗号化往復だけでは書込み成立にならない。
- CRC32は初期・最終XORがともに `0xffffffef`。`zlib.crc32(data, 0x10) ^ 0x10` と一致する。
- `0x1acce551` はCRC初期値ではなく、watchdogに書き込む値。
- 今回のABIでは `MEMERASE=0x40084d02`、`MEMLOCK=0x40084d05`、`MEMUNLOCK=0x40084d06`。書込み後の `0x8e18` は再消去ではなくロック処理。
- `0x96` の実行結果は両領域更新後の再起動要求であり、単なるアプリ再起動と同一視しない。
