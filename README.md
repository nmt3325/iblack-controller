記録対象は **2026年11月10日〜11日（日本時間）**。実機の設定ファイル、スクリプト、保存ログ、systemd journalを照合した内容を掲載しています。

- カメラのセットアップ用Wi-Fiへ接続し、接続先SSIDを `iermu-cam` に設定できた。
- 2026-11-11 **09:06:03**、専用APへの接続を確認した。
- カメラの電源入れ直し後、**09:11:50に同じSSIDへ自動再接続**し、`192.168.10.34` を取得した。追加のSSID書き込みは行っていない。
- 電源入れ直し後の疎通確認は **ping 5/5、損失0%**。
- `iermu.com` / `dvrnat.com` 配下のDNS応答を `192.168.10.1` へ向ける構成と、カメラからの問い合わせを確認した。
- ローカル受信プログラムでTCP接続とUDPパケットの受信を確認した。
- 過去の実行ログで、`rtmp://192.168.10.34:1935/live/live` からH.264映像・AAC音声を短時間受信したことを確認した。

## 利用上の前提

`reference/` は **実機で使用したコード・設定の参照版**です。認証文字列、ホームWi-Fi名、カメラの識別子は例示値に置き換えてあります。例示値のまま本番へコピー・実行しないでください。セットアップ手順内のコマンドは、実設定を保持している既存の `debian-02` を対象にしています。

Git管理用のディレクトリと、稼働中の `/home/nmt3325/iermu_cam` は分離しています。このリポジトリを作成するためのAP再起動やカメラの再設定は行っていません。

## 実装・確認の範囲

- `fakecloud.py` はTCP/UDPの**受信・記録プログラム**です。DNSの応答はdnsmasqが担当します。HTTP/TLSやクラウドAPIの応答機能は実装していません。
- Wi-Fi設定の保持を確認したのは、今回実施したカメラの電源入れ直しです。長期無停止運転や全機種での動作を保証するものではありません。
- 実機の `iermu-ap.service` は `disabled`、DHCPは `static`、受信プログラムは `transient` です。debian-02再起動後の一式自動復旧は、この記録の実施範囲に含めていません。

## リポジトリ内の検査

```bash
python3 tools/verify_repo.py
```

カメラへの接続、Wi-Fi切替、iptables変更は行いません。
